# Deploy Platform — 运维升级发布平台 — 新人使用白皮书

> **版本**: v0.5.1 | **最后更新**: 2026-05-29

---

## 一、平台是什么

Deploy Platform — 运维升级发布平台是一个 **Web 化的自动化升级执行系统**。它把原本需要手动 SSH 到多台服务器、逐服务执行命令的升级流程，变成了在网页上点几下就能完成的操作。

### 平台解决什么问题

- **以前**: 打开 运维文档 → SSH 到 10+ 台服务器 → 逐服务备份/上传/替换/验证 → 2-4 小时
- **现在**: 上传升级包 → 选择服务 → 点击开始 → 实时看日志 → 5-15 分钟

### 核心概念

| 概念 | 说明 | 例子 |
|------|------|------|
| **环境** | 一套独立的服务器集群 | Production、Staging |
| **服务** | 一个可部署的应用单元 | example-service |
| **节点** | 服务运行的具体服务器 | <your-server-ip> |
| **服务类型** | 服务的部署方式 | Go 二进制 / Docker 容器 |
| **升级包** | 要部署的新版本文件 | example-service_v1.2.3.tar.gz |
| **升级任务** | 一次具体的升级操作 | "2026-05-29 Production 环境服务升级" |
| **步骤** | 升级任务中的每个操作 | 备份 → 上传 → 替换 → 验证 → 重启 |

## 二、快速上手：第一次升级

如果你是第一次使用这个平台，按照以下步骤完成一次升级，大约需要 10 分钟。

### 第 1 步：登录 / 注册

1. 打开浏览器访问 `http://<服务器IP>:8000`
2. 首次使用点击「注册」，输入用户名和密码
3. **第一个注册的用户自动成为管理员**
4. 后续注册需要管理员在系统中创建

### 第 2 步：配置环境和服务（仅首次）

进入「系统设置」页面：

**a) 创建环境**
1. 切换到「环境管理」Tab
2. 点击「创建环境」，填写名称（如 Production）和 SSH 端口（默认 22）
3. 可以点击「SSH 测试」验证连接

**b) 创建服务**
1. 进入「服务管理」页面（左侧菜单）
2. 确认右上角环境选择器已切换到目标环境
3. 点击「创建服务」，填写：
   - 服务名称（与服务器上的目录名一致）
   - 服务类型（Go 二进制 或 Docker 容器）
   - 部署路径（如 `/opt/example-service`）
   - 升级顺序（数字越小越先升级）
4. 添加节点：填写服务器的 IP、SSH 端口、用户名和密码
5. 保存

### 第 3 步：上传升级包

1. 进入「升级包管理」页面
2. 点击「上传升级包」
3. 选择目标服务
4. 填写版本号（如 `v1.2.3`）
5. 选择升级包文件（支持 `.tar.gz`、`.zip`、`.tgz`、`.gz`、`.bin`）
6. 上传后会自动计算 MD5

### 第 4 步：创建并执行升级任务

1. 进入「新建升级」页面
2. **步骤一：选择服务** — 勾选本次要升级的服务（按升级顺序排列）
3. **步骤二：关联升级包** — 为每个服务选择对应的升级包版本
4. **步骤三：确认执行** — 设置失败策略：
   - **停止**：任何步骤失败就停下，等待人工处理（推荐）
   - **继续**：跳过失败的步骤，继续执行
   - **回退**：失败后自动回退
5. 点击「开始升级」

### 第 5 步：监控升级进度

1. 进入升级详情页面，左侧是步骤树：
   - ⏳ 等待中
   - 🔄 执行中
   - ✅ 成功
   - ❌ 失败
2. 点击任意步骤，右侧显示该步骤的实时 SSH 日志
3. 底部有控制按钮：**暂停** / **继续** / **停止**

### 第 6 步：完成或回退

- 所有步骤变绿 = 升级成功
- 如果出现问题：
  - 点击「回退」按钮，系统会按逆序恢复备份文件（仅限可回退的步骤）
  - 也可以对单个失败步骤点击「重试」

## 三、各页面功能详解

### 3.1 仪表盘（首页）

登录后的首页，提供全局视图：

- **统计卡片**：环境数、服务数、今日升级任务数
- **最近升级记录**：最近 5 条任务及状态
- **快速入口**：「新建升级」和「一键巡检」
- **环境切换器**：顶部全局环境选择器，切换后所有页面只看当前环境的数据

### 3.2 服务管理

管理系统中的所有服务定义和部署节点。

**列表页**：
- 按环境筛选服务
- 每行显示服务名称、类型标签、节点数、升级顺序
- 支持导入/导出（方便跨环境复制服务配置）

**创建/编辑服务**：
- 基本信息：名称、类型、部署路径
- 运行脚本：run.sh（默认）、启动/停止/检查命令
- 节点配置：添加/编辑/删除节点，每个节点包含 IP、端口、SSH 凭据

### 3.3 升级包管理

管理各服务的升级包文件。

- **上传**：选择服务 → 填写版本号 → 选择文件
- **版本列表**：按服务分组显示，含上传时间、文件大小、MD5
- **删除**：不再需要的旧版本可以删除释放空间
- **限制**：最大 500MB（可在平台设置中修改），支持的格式见平台设置

### 3.4 新建升级

三步向导式创建升级任务：

1. **选择服务**：多选要升级的服务，自动按升级顺序排序
2. **关联升级包**：为每个服务选择对应的升级包版本（也可以不上传新包，直接用旧包）
3. **确认执行**：
   - 预览完整的执行计划（哪些服务 → 哪些节点 → 哪些步骤）
   - 选择失败策略
   - 设置每步超时时间（默认 600 秒）
   - 点击「开始升级」

### 3.5 升级详情（实时监控）

这是平台最核心的页面，分左右两栏：

**左侧 — 步骤树**：
- 三级树形结构：服务 → 节点 → 步骤
- 每步有状态图标和颜色标识
- 失败步骤显示红色，可以点击「重试」

**右侧 — 日志查看器**：
- 终端风格黑色背景
- 选中某个步骤后展示该步骤的 SSH 命令输出
- 实时滚动（WebSocket 推送）
- 支持关键字搜索和日志级别筛选

**操作按钮**：
- 暂停：当前步骤完成后暂停
- 继续：从暂停处继续执行
- 停止：终止整个任务
- 回退：逆序执行可回退步骤
- 重试：对单个失败步骤重新执行

### 3.6 升级历史

查看所有已完成或进行中的升级任务。

- 按环境、状态、时间范围筛选
- 点击任务标题进入详情页
- 删除不需要的历史记录

### 3.7 状态巡检

一键检查所有服务的运行状态。

- 点击「开始巡检」
- 系统 SSH 到每个节点检查：
  - Go 服务：`sh run.sh id` 检查进程是否存在
  - Docker 服务：`docker ps` 检查容器状态
- 结果以卡片形式展示：绿色正常 / 红色异常

### 3.8 审计日志

记录所有关键操作，方便追溯：

- 谁（用户名）
- 什么时候（精确到秒）
- 做了什么（创建/修改/删除/执行）
- 对什么做的（环境/服务/升级任务）
- 从哪个 IP 操作的

支持按操作类型筛选（如只看「删除」操作）。

### 3.9 系统设置

四个 Tab 页，仅管理员可见：

**环境管理**：创建/编辑/删除环境，SSH 连接测试

**用户管理**：创建/编辑/删除用户，设置角色（管理员/操作员）

**服务类型**（v0.5.1 新增）：
- 查看所有服务类型及步骤定义
- 创建自定义类型（如 java、python）
- 编辑步骤序列和可回退步骤
- 内置的 go/docker 不可删除

**平台设置**（v0.5.1 新增）：
- 品牌缩写（显示在 Logo 处）
- 平台标题（浏览器标签页标题）
- 远程更新目录（升级包在目标服务器上的存放路径）
- 最大上传大小（MB）
- 允许上传的文件扩展名

修改后保存立即生效，部分设置（品牌、标题）刷新页面即可看到。

## 五、Go 服务和 Docker 服务的升级流程

### Go 二进制服务（9 步）

| 步骤 | 说明 | 实际命令 |
|------|------|---------|
| precheck | 预检查 | 记录当前版本和 PID |
| backup | 备份 | `cp binary binary.YYYYMMDD` |
| upload | 上传 | SCP 上传新 binary |
| copy | 替换 | `cp /opt/update/.../binary /opt/service/` |
| verify | 校验 | MD5 比对 |
| verify_version | 版本验证 | `./binary -v` |
| stop | 停服 | `sh run.sh stop` |
| check_start | 启动验证 | 等待进程监控自动拉起 |
| log_check | 日志检查 | 检查日志中的启动成功标志 |

### Docker 容器服务（6 步）

| 步骤 | 说明 | 实际命令 |
|------|------|---------|
| docker_scp | 上传镜像 | SCP 上传 tar.gz |
| docker_load | 导入镜像 | `docker load -i image.tar.gz` |
| docker_verify | 镜像验证 | `docker images \| grep service` |
| precheck | 预检查 | `docker ps \| grep service` |
| switch_container | 切换容器 | `sh run.sh <old> <new>` |
| container_check | 容器验证 | `docker ps \| grep service` |

## 六、常见问题

### Q: 升级失败了怎么办？

1. 先看失败的步骤日志，判断原因（网络问题、文件问题、脚本问题）
2. 如果是网络波动或临时问题，点击该步骤的「重试」
3. 如果是文件问题（如升级包错误），点击「回退」恢复旧版本
4. 回退只会恢复可回退的步骤（备份、上传、替换），Docker 服务回退会自动切回旧容器

### Q: 如何添加新的服务类型？

进入「系统设置 → 服务类型」，点击「创建类型」：
1. 输入类型名称（如 `java`）
2. 输入显示标签（如 `Java 应用`）
3. 选择升级步骤（可以多选已有的步骤 key，也可以输入新的 step key）
4. 勾选哪些步骤支持回退
5. 保存后，创建服务时就能选择新的类型了

### Q: 添加新服务时「升级顺序」怎么填？

- 数字越小越先升级
- 没有依赖关系的服务可以用相同数字
- 如果服务 A 依赖服务 B，A 的顺序应该大于 B（A 后升级）
- 可以在 `depends_on` 字段填写前置服务名，系统会按依赖关系自动排序

### Q: 多个节点是并行升级还是串行？

同一服务的同一类型步骤在多个节点上**并行执行**。例如，sms 服务有 3 个节点，backup 步骤会在 3 个节点上同时执行。

### Q: 忘记了密码怎么办？

联系管理员在「系统设置 → 用户管理」中重置密码。管理员账号无法自行找回密码，请联系部署人员通过 API 或数据库操作。

### Q: 升级包上传后存在哪里？

上传的文件存储在服务器的 `uploads/` 目录中，数据库记录文件路径和 MD5。升级执行时通过 SCP 分发到目标服务器。

### Q: 平台如何保证安全？

- 所有 SSH 密码使用 AES-256-GCM 加密存储
- 用户密码使用 bcrypt 哈希
- 所有关键操作自动记录审计日志
- 登录有失败次数限制（5 分钟 5 次）
- 建议生产环境前置 Nginx + HTTPS

## 七、最佳实践

1. **升级前先巡检**：在「状态巡检」页面确认所有服务正常运行后再升级
2. **先升级非关键服务**：upgrade_order 把不重要的服务放在前面
3. **使用「停止」策略**：升级初期建议使用 stop 策略，出现问题可以人工判断
4. **保留旧升级包**：不要立即删除旧版本的升级包，确认新版本稳定后再清理
5. **设置合理的超时**：大文件上传或 Docker load 可能需要更长时间
6. **升级后巡检**：升级完成后执行一次巡检，确认所有服务正常
7. **记录版本号**：升级包版本号保持统一规范，如 `v1.2.3` 或 `20260529`
