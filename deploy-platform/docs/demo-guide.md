# Deploy Platform — 运维升级发布平台 — 演示操作指南

> **版本**: v0.5.1 | **最后更新**: 2026-05-29

---

## 操作场景

本文档模拟一次完整的升级操作：在 **Production 环境**中对 **example-service**（Go 二进制服务）执行版本升级，从 `v1.0.0` 升级到 `v1.1.0`。

> 文档中标注了 **📷 截图点**，请在测试环境操作时在此处截图。

---

## 一、登录与注册

### 操作步骤

1. 打开浏览器，访问 `http://<your-server-ip>:8000`
2. 首次使用点击「注册」按钮
3. 输入用户名 `admin` 和密码，点击注册
4. 注册成功后自动跳转到仪表盘

### 操作说明

系统采用自助注册机制，第一个注册的用户自动成为管理员，拥有全部权限。后续注册需要管理员在系统中创建。

**📷 截图点 1**：登录/注册页面全貌

## 二、仪表盘概览

### 操作步骤

登录后进入仪表盘（首页），浏览以下区域：

- **顶部**：环境选择器（默认无环境，后续配置后会显示 Production/Staging）
- **左侧**：统计卡片（环境数、服务数、升级包数、今日任务数）
- **右侧**：最近升级记录列表
- **底部**：快速操作入口（新建升级、一键巡检）

### 操作说明

仪表盘是全局视图，顶部环境选择器切换后，所有页面只看当前环境的数据。

**📷 截图点 2**：仪表盘全貌（含左侧菜单展开状态）

## 三、创建环境

### 操作步骤

1. 点击左侧菜单「系统设置」
2. 切换到「环境管理」Tab
3. 点击「创建环境」按钮
4. 填写环境信息：
   - **名称**：`Production`
   - **描述**：`Production 环境`
   - **SSH 端口**：`22`（默认）
5. 点击「保存」

### 操作说明

环境代表一套独立的服务器集群。Production 和 Staging 各有一套独立的服务和节点配置。

**📷 截图点 3**：创建环境的弹窗，已填写好信息

---

## 四、SSH 连接测试

### 操作步骤

1. 在环境列表中，点击 Production 环境行的「SSH 测试」按钮
2. 在弹出的对话框中输入：
   - **主机**：`<your-server-ip>`
   - **端口**：`22`
   - **用户**：`root`
   - **密码**：输入目标服务器的 SSH 密码
3. 点击「测试连接」
4. 看到绿色提示"连接成功，延迟: Xms"

### 操作说明

SSH 测试用于验证平台能正常连接到目标服务器。测试通过后才说明环境配置正确。

**📷 截图点 4**：SSH 测试弹窗，显示连接成功的结果

---

## 五、创建服务并添加节点

### 操作步骤

1. 点击左侧菜单「服务管理」
2. 确认右上角环境选择器已切换为「Production」
3. 点击「创建服务」按钮
4. 填写服务基本信息：
   - **服务名称**：`example-service`
   - **服务类型**：选择 `Go 二进制`
   - **部署路径**：`/opt/example-service`
   - **运行脚本**：`run.sh`（默认）
   - **升级顺序**：`1`
   - **描述**：`示例服务`
5. 在「节点配置」区域点击「添加节点」：
   - **主机 IP**：`<your-server-ip>`
   - **SSH 端口**：`22`
   - **SSH 用户**：`root`
   - **SSH 密码**：输入目标服务器的 SSH 密码
6. 点击「保存」

### 操作说明

- **升级顺序**：数字越小越先升级。有依赖关系的服务应设置合理的顺序。
- **节点**：一个服务可以有多个节点（多台服务器），升级时同一步骤会在所有节点上并行执行。

**📷 截图点 5**：创建服务弹窗，已填写完整信息（含节点配置）

## 六、服务列表

### 操作步骤

服务创建完成后，返回服务列表页面，可以看到：

- 服务按环境筛选显示
- 每行显示：服务名称、类型标签（Go 二进制/Docker 容器）、节点数、升级顺序、操作按钮
- 支持编辑、删除、导入/导出

**📷 截图点 6**：服务列表页面，至少显示 2-3 个服务（如果没有其他服务，显示刚创建的这一个即可）

## 七、上传升级包

### 操作步骤

1. 点击左侧菜单「升级包管理」
2. 点击「上传升级包」按钮
3. 在弹出的对话框中：
   - **选择服务**：选择 `example-service`
   - **版本号**：输入 `v1.1.0`
   - **选择文件**：点击选择提前准备好的升级包文件（如 `.tar.gz`）
4. 点击「上传」
5. 上传成功后，列表中显示该升级包记录，包含版本号、文件大小、MD5 校验值

### 操作说明

- 支持的文件格式：`.tar.gz`、`.zip`、`.tgz`、`.gz`、`.bin`，最大 500MB
- 同一服务的同一版本号不能重复上传
- 上传后自动计算 MD5 校验值，用于后续的完整性校验

**📷 截图点 7**：上传升级包弹窗，已选择服务和文件

**📷 截图点 8**：升级包列表页面，显示已上传的升级包记录

## 八、创建升级任务（三步向导）

### 步骤一：选择服务

1. 点击左侧菜单「新建升级」
2. 确认环境为「Production」
3. 在服务列表中勾选 `example-service`
4. 设置失败策略为「停止」（推荐首次使用）
5. 点击「下一步」

**📷 截图点 9**：步骤一「选择服务」页面，已勾选服务

### 步骤二：关联升级包

1. 为 `example-service` 选择刚上传的 `v1.1.0` 升级包
2. 可以查看升级包的 MD5 和上传时间
3. 点击「下一步」

**📷 截图点 10**：步骤二「关联升级包」页面，已选择对应的升级包版本

### 步骤三：确认并执行

1. 查看自动生成的执行计划预览：
   - 服务名称、节点 IP
   - 升级步骤序列（precheck → backup → upload → copy → verify → verify_version → stop → check_start → log_check）
2. 确认失败策略和超时时间
3. 点击「开始升级」

**📷 截图点 11**：步骤三「确认执行」页面，展示完整的执行计划预览

## 九、实时监控升级进度

### 操作步骤

点击「开始升级」后，自动跳转到升级详情页面：

**左侧 — 步骤树：**
- 三级树形结构：服务 → 节点 → 步骤
- 每个步骤有状态图标：
  - ⏳ 灰色 = 等待中
  - 🔄 蓝色旋转 = 执行中
  - ✅ 绿色 = 成功
  - ❌ 红色 = 失败

**右侧 — 日志查看器：**
- 终端风格黑色背景
- 点击某个步骤，右侧显示该步骤的实时 SSH 命令输出
- 日志通过 WebSocket 实时推送，无需刷新

**底部操作栏：**
- 暂停：当前步骤完成后暂停
- 继续：从暂停处继续执行
- 停止：终止整个任务

### 操作说明

- 同一服务的同一类型步骤在多个节点上**并行执行**
- 日志支持关键字搜索和级别筛选
- 任务完成后，所有步骤状态变为绿色 ✅

**📷 截图点 12**：升级详情页面，步骤正在执行中（左侧步骤树有蓝色旋转图标，右侧显示实时日志）

**📷 截图点 13**：升级详情页面，所有步骤执行完成（全绿 ✅），日志显示成功信息

## 十、升级历史

### 操作步骤

1. 点击左侧菜单「升级历史」
2. 查看所有已完成和进行中的任务列表
3. 列表包含：任务标题、环境、状态标签、开始时间、完成时间
4. 可以按环境、状态、时间范围筛选
5. 点击任务标题可进入详情页查看完整日志

**📷 截图点 14**：升级历史页面，显示已完成的任务记录

## 十一、状态巡检

### 操作步骤

1. 点击左侧菜单「状态巡检」
2. 点击「开始巡检」按钮
3. 系统自动 SSH 到 Production 环境所有节点检查服务状态：
   - Go 服务：执行 `sh run.sh id` 检查进程
   - Docker 服务：执行 `docker ps` 检查容器
4. 巡检结果以卡片形式展示：
   - 🟢 绿色卡片 = 服务正常
   - 🔴 红色卡片 = 服务异常（显示错误信息）

**📷 截图点 15**：巡检结果页面，服务卡片全部绿色正常

---

## 十二、操作审计

### 操作步骤

1. 点击左侧菜单「操作审计」
2. 查看系统自动记录的所有关键操作：
   - 谁（用户名）
   - 什么时候（精确到秒）
   - 做了什么操作
   - 对什么资源
   - 详细信息
3. 支持按操作类型筛选（如只看"删除"操作）

### 操作说明

这次演示过程中的所有操作（创建环境、创建服务、上传升级包、执行升级等）都已自动记录在审计日志中，方便追溯。

**📷 截图点 16**：审计日志页面，显示本次演示操作产生的日志记录

## 十三、平台设置

### 操作步骤

1. 点击左侧菜单「系统设置」
2. 切换到「平台设置」Tab
3. 查看当前平台配置：
   - **品牌缩写**：显示在 Logo 处
   - **平台标题**：浏览器标签页标题
   - **远程更新目录**：升级包在目标服务器的存放路径
   - **最大上传大小**：升级包文件大小限制
   - **允许上传的扩展名**：支持的文件格式
4. 可以在此页面直接修改配置，保存后立即生效

**📷 截图点 17**：平台设置 Tab 页面，显示当前配置信息

### 服务类型管理

1. 切换到「服务类型」Tab
2. 查看内置的 `go`（Go 二进制）和 `docker`（Docker 容器）两种类型
3. 可以创建自定义服务类型，定义专属的升级步骤序列

**📷 截图点 18**：服务类型 Tab 页面，显示内置类型的步骤列表
